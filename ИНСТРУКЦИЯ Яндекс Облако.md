# Посредник в Яндекс Облаке: синхронизация без VPN

**Зачем.** Supabase (наша общая база) работает через Cloudflare, а российские операторы часто режут к нему соединения. Тогда без VPN приложение не может ни отправить, ни получить данные. Посредник — это «шлюз» в Яндекс Облаке: телефон обращается к нему (это российский сервис, его не режут), а он уже сам ходит в Supabase.

**Сколько стоит.** Первые 100 000 запросов в месяц бесплатно. Приложение, пока оно открыто на экране, делает около 120 запросов в час; на двоих обычно выходит несколько тысяч в месяц. Сверх бесплатного — 142,3 ₽ за миллион запросов, то есть копейки. Нужна банковская карта для платёжного аккаунта.

**Сколько времени.** Около 20 минут. Делать удобнее на компьютере.

**Сначала убедитесь, что он нужен.** В приложении: Настройки → «Проверить связь», **VPN выключен**. Если строки «База напрямую» зелёные и внизу «Всё доступно» — посредник не нужен.

---

## Шаг 1. Аккаунт в Яндекс Облаке

1. Откройте [console.yandex.cloud](https://console.yandex.cloud) и войдите своим Яндекс ID.
2. При первом входе облако предложит создать **облако** и **каталог** — соглашайтесь с названиями по умолчанию (каталог будет называться `default`).
3. Создайте **платёжный аккаунт**: слева «Биллинг» (Billing) → «Создать аккаунт» → тип **физическое лицо** → привяжите карту. Банк может временно заблокировать небольшую сумму для проверки карты.
4. Дождитесь, пока у платёжного аккаунта будет статус **«Активен»** (или «Пробный период»). Без этого шлюз не создастся.
5. Желательно: «Биллинг» → «Бюджеты» → создайте бюджет, например 50 ₽ в месяц, с уведомлением на почту. Тогда вы узнаете, если что-то пойдёт не так.

## Шаг 2. Создать шлюз

1. В консоли откройте каталог `default` → «Все сервисы» → **API Gateway** → **«Создать API-шлюз»**.
2. **Имя:** `kuhnya` (только латиница, строчные буквы).
3. В поле **«Спецификация»** сотрите пример и вставьте текст **целиком**, ничего не меняя. Отступы (пробелы в начале строк) важны.
   Удобнее всего взять его из файла **«Спецификация шлюза Яндекс.yaml»** в папке проекта: открыть Блокнотом → Ctrl+A → Ctrl+C. Если копируете отсюда — без строк с тремя обратными кавычками ```` ``` ```` (это не часть спецификации; с ними будет ошибка «found character '`' that cannot start any token»). Первая строка должна быть `openapi: 3.0.0`.

```yaml
openapi: 3.0.0
info:
  title: kuhnya
  version: 1.0.0
paths:
  /{path+}:
    x-yc-apigateway-any-method:
      x-yc-apigateway-integration:
        type: http
        url: https://xjwbpjmajdxplhzcdivb.supabase.co/{path}
        headers:
          '*': '*'
          Host: xjwbpjmajdxplhzcdivb.supabase.co
        query:
          '*': '*'
        timeouts:
          connect: 10
          read: 60
      parameters:
        - name: path
          in: path
          required: false
          schema:
            type: string
```

Что тут написано: «любой запрос на любой адрес шлюза переслать в нашу базу Supabase по тому же пути, со всеми заголовками и параметрами».

4. Нажмите **«Создать»**. Через несколько секунд у шлюза будет статус «Active».

## Шаг 3. Проверить шлюз (на компьютере, VPN можно не выключать)

1. Откройте созданный шлюз. На странице «Обзор» найдите **«Служебный домен»** — адрес вида `https://d5dxxxxxxxxxxxxxxxxx.apigw.yandexcloud.net`. Скопируйте его.
2. Вставьте в адресную строку браузера этот адрес и допишите в конце `/auth/v1/health`, например:
   `https://d5dxxxxxxxxxxxxxxxxx.apigw.yandexcloud.net/auth/v1/health`
3. Должно открыться короткое сообщение со словами **«API key»** (например, `No API key found in request`). Это хорошо: запрос дошёл через шлюз до Supabase, а тот просит ключ, который приложение пришлёт само.
4. Если вместо этого ошибка — см. «Если не заработало» ниже.

## Шаг 4. Включить посредника в приложении

**Проще всего:** пришлите мне служебный домен из шага 3 — я впишу его и соберу папку для GitHub.

**Или сами:**

1. В папке проекта откройте файл `js\config.js` Блокнотом.
2. Найдите строку `proxyUrl: '',` и вставьте домен между кавычками, **без косой черты в конце**:
   `proxyUrl: 'https://d5dxxxxxxxxxxxxxxxxx.apigw.yandexcloud.net',`
   Строки `supabaseUrl` и `supabaseAnonKey` **не трогайте**.
3. Сохраните файл, запустите «Собрать папку для GitHub.cmd» и загрузите папку «для GitHub» в репозиторий, как обычно.
4. Через 1–2 минуты закройте приложение на телефоне и откройте снова. **Входить заново не нужно** — вход сохранится.

## Шаг 5. Проверить в приложении

1. Выключите VPN.
2. Настройки → **«Проверить связь»**. Строки «Посредник: короткий запрос» и «Посредник: данные» должны быть зелёными, внизу — **«Посредник работает»**.
3. Добавьте что-нибудь в покупки на одном телефоне — на втором оно появится в течение 30 секунд (или сразу, если нажать на «Настройки → Синхронизировать сейчас»).

## Что меняется с посредником

- Изменения второго человека появляются **в течение 30 секунд**, а не мгновенно: «живое» обновление через шлюз не проходит, поэтому приложение каждые 30 секунд коротким запросом проверяет, не изменилось ли что-то, и только тогда загружает данные.
- **Фото блюд** показываются и загружаются через посредника. В данных по-прежнему хранится адрес Supabase, поэтому, если посредника когда-нибудь убрать, фото не пропадут.
- **Telegram-бот, напоминания и резервные копии** работают как раньше: они выполняются на серверах GitHub и Supabase, посредник им не нужен.
- **Загрузка рецепта по ссылке** тоже идёт через посредника.

## Если не заработало

| Что видно | Что сделать |
|---|---|
| В шаге 3 ошибка **404** или «Not Found» | Спецификация вставлена не целиком или сбились отступы. Откройте шлюз → «Редактировать», вставьте текст из шага 2 заново, сохраните. |
| В шаге 3 ошибка **500 / 502 / 504** | Проверьте в спецификации строку `url:` — там должен быть адрес вашей базы, как в шаге 2. Подождите минуту и попробуйте снова. |
| В шаге 3 открывается, а в приложении **«Посредник не отвечает»** | Проверьте адрес в `proxyUrl`: точно как служебный домен, начинается с `https://`, без `/` в конце. Убедитесь, что обновлённый сайт загружен на GitHub (закройте и откройте приложение). |
| **«Посредник отвечает, но данные через него не идут»** (ошибка 401/403) | Шлюз не передаёт заголовки. Проверьте в спецификации блоки `headers:` и `query:` со строками `'*': '*'`. |
| Всё по-прежнему не работает | Откройте сайт приложения на компьютере, нажмите F12 → вкладка «Console». Если там есть слова **«blocked by CORS policy»** — добавьте в спецификацию блок из раздела ниже. Если что-то другое — пришлите мне снимок экрана этой вкладки и результат «Проверить связь». |

### Дополнительный блок, если есть ошибка CORS

Вставьте эти строки в спецификацию **между** строкой `version: 1.0.0` и строкой `paths:` (с тем же отступом, что у `info:` — то есть без отступа слева), сохраните шлюз:

```yaml
x-yc-apigateway:
  cors:
    origin: true
    methods: [GET, POST, PUT, PATCH, DELETE, HEAD, OPTIONS]
    allowedHeaders: [authorization, apikey, content-type, prefer, range, x-client-info, x-upsert, accept-profile, content-profile, cache-control, x-supabase-api-version]
    exposedHeaders: [content-range, content-type, x-supabase-api-version]
    maxAge: 3600
```

### Как отключить посредника

В `js\config.js` сделайте снова `proxyUrl: '',`, соберите папку и загрузите на GitHub. Приложение вернётся к прямому подключению; данные и вход сохранятся. Сам шлюз можно удалить в консоли Яндекс Облака (API Gateway → шлюз → «Удалить»).
